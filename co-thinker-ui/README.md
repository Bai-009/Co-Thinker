# Co-Thinker 前端

带着还没说清的想法进来，一边说一边想；后台异步维护逐渐形成的理解；需要行动时再综合成 Brief。

```bash
npm install
npm run dev      # http://127.0.0.1:5180
npm run build
npm test
```

当前是**示例模式**：一个跑在浏览器里的模拟传输层，没有连接任何模型。界面上有明确标注。

## 设计推导

前两版都没有系统。第一版是「克制的编辑排版」的一套主张，被否；第二版照着 Claude 桌面端逐像素量参数，
数值对了，但那是别人系统里的数值，搬过来没有内部逻辑。把自己的刻度摊开一看就露馅：

| | 第二版 | 相邻比 / 差 |
|---|---|---|
| 字号 | 12 / 13 / 16 / 17 / 19 | ×1.083 / ×1.231 / ×1.062 / ×1.118 |
| 灰阶 L | 17 / 43 / 60.5 / 73.5 / 88 / 92.8 / 96.6 / 98.9 | +26 / +17.5 / +13 / +14.5 / +4.8 / +3.8 / +2.3 |

字号没有统一比率。灰阶更糟——OKLCH 的 L 感知均匀，这些差值就是人眼看到的对比台阶。

这一版的所有数值从三条外部规则推出来：

**一、行长取字号的整数倍。** [clreq](https://w3c.github.io/clreq/zh/) 的原话，否则行首行尾对不齐。
上一版 670 ÷ 16 = 41.875 字。现在：`17 × 36 = 18 × 34 = 612px`——前台后台共用一条栏宽，切换时栏不跳，
变的只是每行字数。

**二、行距取字号的 50–100%。** 同样出自 clreq；[Typotheque](https://www.typotheque.com/articles/typesetting-cjk-text-cn)
补充说 CJK 要 ≥1.7 倍，因为汉字信息密度高、要撑满全角字框，拉丁文默认的 120% 不够。上一版 1.5 是地板值，
从一个以拉丁文为主的界面上抄来的。clreq 还说行长短、字号小时行距才往下取——**这正好把产品的两种时间分开了**：

| | 字号 | 行高 | 行距 | 依据 |
|---|---|---|---|---|
| 前台 · 说话 | 17 sans | 28px (1.647) | 65% | 短句往返，取下半段 |
| 后台 · 地基与 Brief | 18 serif | 32px (1.778) | 78% | 连续阅读，取上半段 |

衬线的 18 不是破坏刻度，是光学补偿：同字号下衬线显小。

**三、灰阶按它要达到的对比度反解，不按等差填。**

| | L | 对纸 | 干什么 |
|---|---|---|---|
| `--ink` | 18 | 18.3:1 | 正文，拉满 |
| `--ink-2` | 45.5 | 7.1:1 | 次要正文，AAA |
| `--ink-3` | 56 | 4.5:1 | 元信息，AA 底线 |
| `--ink-4` | 78.5 | 1.9:1 | 禁用与装饰，**明确不承担文字** |
| `--rule` 系 | 86 / 92.5 / 96.5 | 1.5 / 1.2 / 1.08:1 | 只做结构，压到看不见 |

朱是 `oklch(51% 0.125 38)`：白字压在上面 6.1:1，作文字对纸 5.9:1。深色一套用同样的目标反解。

**字号只有一个比率 1.2**，基准 17：`14 / 17 / 20 / 24`。再细的层级交给字重和墨色，不再加档。
全部 CSS 里只剩 `1em` 和 `0.8235em`（= 14/17，刻度上的一档）两个相对值。

**纵向节奏以「行」为单位**（[赫蹏](https://sivan.github.io/heti/)的做法）：段 = 半行 14px，
消息 = 一行 28px，轮次 = 两行 56px。间距刻度另走 4px 栅格——间距要的是栅格，不是几何级数。

**线只在间距分不了组的地方用。** 判断列表、比较材料原来靠横线分隔，现在靠一行的空当；正文里一条横线都没有，
面板也不该有两套分组信号。剩下的线只有三处：`<hr>`（显式内容）、表格单元格（表格结构）、面板头（两类内容的边界）。

**输入是浮起来的一张面。** 比纸亮、10px 圆角、一道淡边、一层淡投影；发送是右侧圆形图标钮。
提示、后台状态和快捷键在框外那一行。这一条来自第二版，保留。

**栏永远在窗口正中**，边注绝对定位在左边距里不参与居中；正文在栏顶栏底淡出，不被硬切。

    sessionReducer.ts  单一事实来源 + 确定性门禁

### 引用契约

```ts
type Reference = {
  sessionId: string
  sourceId: string        // 消息的持久 id，不是文本查找
  sourceVersion: number   // 引用时的文本版本
  range?: { start: number; end: number }  // 规范化源文本上的 UTF-16 半开区间
  quote: string
}
```

偏移落在**规范化源文本**上，不用含控件的 DOM 偏移：渲染时每个文本 run 带 `data-o`，选区因此能精确还原。所以同一句话在两条消息里出现，引用仍然回到被选中的那一条；源被改写之后界面说「引用依据已改变」，不静默跳到另一句相似的话。

### 确定性门禁

后台结果要同时满足才写得进去：会话一致、历史修订号一致、版本与覆盖范围不倒退。回改会把源消息版本 +1、`historyRevision` +1，在途的旧任务因此失去资格。重试用同一个幂等键，不会多出一条重复的输入。

阶段机：`idle → submitting → streaming → complete`，取消先进 `cancelling`。停止会把半句话按中断存下来，不是只停住动画。

### Brief 的版本关系

请求时冻结 `historyRevision` / `cutoffSequence` / `groundworkVersion`。之后新增内容说「有新增内容」，采用过的原话被改说「引用依据已改变」——两种关系要做的事不一样，不笼统叫「过期」。复制和下载用的是眼前这份快照。

## 示例模式的边界

- 输入与脚本对得上，才给脚本里的回应；对不上就明说没有连接模型，并且**不推进地基**——那条表达因此真的留在「尚未沉淀」里。
- 剧情由适配器产生，展示组件不用定时器或关键词编排。
- 页脚的「示例控制」跟产品交互分开：填入下一句、让下一轮生成失败、让下一次地基更新失败。
- 两段讨论：城市观察（含比较材料、一次改口）和评审清单（含列表与表格，文本更长）。前者故意让同一句话出现两次，用来检验引用能不能分清。

## 检查过什么

- `npm test` 30 项通过，`npm run build` 通过，`tsc` 无错。
  覆盖：规范化偏移、同句两处的引用定位、源改版后失效、门禁（过期修订号 / 换会话 / 版本倒退 / 覆盖范围倒退）、幂等重试、回改使在途任务失效、停止后半句留存、刷新不假装在生成、Brief 快照冻结与未沉淀表达、中文输入法不误提交、切视图保草稿、取消修改还原草稿。
- 浏览器实走：空会话 → 三轮讨论 → 展开比较 → 地基 → 过往；1440 / 1000 / 375 CSS 像素，浅色与深色；无横向溢出，控制台无报错。
- 版面数值用 `getComputedStyle` 核对过：栏 x=165 / w=670（窗口 1000），输入框底色 `oklch(1 0 90)` 高于页面 `oklch(0.989 …)`，行高 24px / 字号 16px。

## 还没做到的

- 默认不接模型；示例文案不能证明模型的理解、异议或归纳质量。`?live` 接的是 `backend/`（DeepSeek），失败路径走过，成功路径还没实测。
- 只实现最近一次用户输入的回改，没有任意历史分支编辑器。
- 服务侧的 context assembly 由 `backend/` 的 thinker / rewriter 提示词决定；「所指材料」（引用）目前只留在客户端，不随请求发给模型。
- 表面语言参照了 Claude 桌面端量出来的数值，内容结构（边注、地基、Brief、引用）是这个产品自己的，没有照抄那套界面。
- 审美仍待评价。测试通过和构建通过都不代表它好看。

### co-thinker-ui：新前端怎么跑

```bash
cd co-thinker-ui && npm install && npm run dev      # http://127.0.0.1:5180
```

- 默认是**示例模式**：独立的模拟传输层，不连模型；顶栏有「示例 · 未连接模型」。打的字正好是脚本里的那句才推进，其他输入得到诚实的提示。
- **实测**：先按上面的步骤起后端（`.env` 里填 `DEEPSEEK_API_KEY`），再打开 `http://127.0.0.1:5180/?live`（或在 `co-thinker-ui/.env.local` 写 `VITE_TRANSPORT=live`）。Vite 把 `/api` 代理到 8000，SSE 也走这里。
- 真实传输层在 `src/transport/httpTransport.ts`：服务端只有消息正文、地基正文和记忆状态；id / sequence / version（正文指纹）和按轮的地基历史在客户端补出来，界面对示例与真实一视同仁。
- `npm test`（Vitest）、`npm run typecheck`。
