## 本轮的整体设计

详见 [设计依据与取舍](EXPERIENCE-DIRECTION.md)。

对话与思考页构成同一个工作空间：对话保留即时表达，思考页承接正在讨论的问题、手边材料和异步记录。历史作为导航抽屉；宽屏并置，窄屏按需打开。标题固定保留当前讨论对象，阅读历史时不会被自动拖回底部。

视觉统一为浅石色、深墨色与少量墨绿，正文采用本地中文字体，品牌用系统衬线字体。重新组织原样式文件，避免叠加历次布局覆盖；颜色、字体、间距及运动由 `frontend/src/workbench/tokens.css` 维护。保留深色外观、键盘焦点与减少运动偏好。

## 从讨论材料到下一轮

1. 整段回复或选中的原话可以“留在手边”，保留原文和来源。
2. 手边改写另存为改写稿；原对话不被替换。可回到原文，移出后可以撤销。
3. “聊这一点”把材料带入输入区；发送时明确区分引用材料与新的表达。界面以引用块显示，原始请求保留“引用不代表认同”的语义。
4. 材料按会话隔离，并区分正式模式和预览；存于当前浏览器，存储失败会明确显示。它不自动进入模型记忆，不代表已确认约束。
5. 原文定位可以处理跨 Markdown 加粗的选中文字；原文被修订时明确显示不可定位，不能误指向后来的转引。

思考页继续使用既有的异步记忆与会话版本机制。本轮在 Prompt 中澄清了共同语气与来源的关系，并规定引用、假设、短促回应和改写不单独构成确认；这属于语义规则改进，不是代码已证明模型能够正确判断。

## 验证结果

- 前端 37 项测试通过；本轮新增用例覆盖会话/预览隔离、改写保留来源、刷新与撤销、存储失败、引用与反对表达的分离、跨强调文字的原文定位。
- 后端 59 项测试通过，既有轮次快照、版本失效、取消、回改与失败保留机制仍通过回归。
- `npm run build` 通过，`git diff --check` 通过。
- 浏览器实际验证：留在手边 → 改写 → 引用发送；返回原文；新会话不显示上一会话材料，返回后恢复；移出与撤销；Brief 流式完成及操作入口；浅深外观；窄屏思考页抽屉。
- 窄屏和桌面检查没有观察到横向溢出，运行日志没有前端 error。IAB 的缩放使请求尺寸和 CSS 尺寸不同，因此依据实际 CSS 宽度核查（观察范围包含约 266–853px 的窄屏/中屏），不把请求的 320/375/414/768 当作精确实测值。临时 viewport 覆盖已重置。

## 当前边界
